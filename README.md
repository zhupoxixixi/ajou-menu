# Ajou Menu · 亚洲大学食堂菜单

**[打开网站，直接查看菜单 →](https://zhupoxixixi.github.io/ajou-menu/)**

已部署到 GitHub Pages，电脑和手机浏览器都可以直接使用。**无需下载源码、安装程序或填写 API 密钥。**

## 如何使用

1. 点击右上角的 **中文 / 한국어** 切换语言。中文界面只显示中文菜名；需要韩文时切换到韩文界面。切换后刷新仍保留所选语言，也不会把自动选餐固定成某一天的菜单。
2. 选择 **宿舍食堂 / 教职工食堂**，再选择餐次和窗口。餐次只列出当天有菜品的选项；教职工食堂的营业说明在顶部信息弹窗中查看。窗口超过一行时可左右滑动，当前窗口会保持在可见区域内。
3. 用内容顶部的左右按钮切换日期，或点击 **选择日期** 打开日历。手机上显示底部日历面板，电脑上显示弹窗。
4. 点击“星期几菜单”标题行最右侧的 **复制图标**，复制日期、食堂、餐次、窗口及菜名，不附带声明或网页链接。右上角还可以切换深浅主题。
5. 手动查看后，点击日历里的 **回到当前餐次** 恢复自动选餐。菜单上的状态按韩国时间和公布时段计算，不代表现场实时营业情况。
6. 点击顶部信息按钮，查看所选日期两间食堂的抓取状态、更新时间、中文完整度，或刷新已发布菜单。

## 手机与离线

- iPhone：用 Safari 打开网页，选择 **分享 → 添加到主屏幕**。以主屏应用打开时保留独立图标。
- Android 等支持安装的浏览器：使用浏览器的安装菜单，或“使用与更新”里的安装按钮（浏览器允许时显示）。
- 联网打开一次、显示“菜单已准备好供离线查看”后，可断网重新打开已保存的一周菜单。离线期间不能获取临时调整；页面会标明离线状态和原始更新时间。
- 线上优先加载最新页面和菜单，只有连接失败时使用缓存；缓存仅属于 `/ajou-menu/`，不影响公告站。
- 缓存存储异常时仍可加载在线菜单；单个标签页使用旧缓存，只通知受影响的页面。
- 采用浅色页头、绿色选中状态，支持深浅主题和轻量弹窗动效；系统开启“减少动态效果”时关闭动画。
- 不提供手机主动推送。

默认进入宿舍食堂，按**韩国时间**和供餐截止时间显示当前或下一餐：早餐结束后显示午餐，午餐结束后显示晚餐，晚餐结束后显示次日第一餐。教职工食堂不供应早餐，次日默认午餐；有 A/B 窗口时优先 A。每天的供餐时间优先读取当天公告，页面显示对应时段。

次日菜单尚未公布时，仍显示次日日期并提示暂无菜单。手动选择日期、餐次、窗口或打开分享链接后，切换食堂仍保留所选日期和餐次；该食堂当天有菜单但不供应所选餐次时，明确提示“不供应早餐”等信息。点击日历中的 **回到当前餐次** 恢复自动选择；自动模式下切换食堂，按各自的供餐时间重新选餐。

周末抓取成功且全天无菜品，或当天有明确休业公告时，显示 **节假日不营业**，收起餐次、窗口、供餐时间和复制按钮，保留食堂切换及日期导航。未来工作日尚无菜单时显示 **菜单尚未公布**；历史日期缺少来源数据、抓取失败与休业分别提示。

学校页面不再提供某天菜单时，保留此前发布过的同一天菜品和原始抓取时间，并标注“学校页面已无当天菜单”。空页面本身不作为工作日休业或学校保留期限的证据。

## 菜单来源与更新

- 原始来源：[亚洲大学官方食堂公告](https://www.ajou.ac.kr/kr/life/food.do)。
- 仓库配置了每日韩国时间 **00:00（KST）** 的自动更新任务，实际执行时间可能延迟。
- 周末如已获取下周菜单，可以查看 **下周预告**。
- 每日抓取覆盖周一到周日，周末是否供餐以学校公告为准。
- 菜单获取失败、译文暂缺或显示旧数据时，页面会提供提示。
- 超过 36 小时没有更新时提示检查；更新时间始终保留，刷新网页不会把旧数据伪装成新抓取。

这是非官方菜单助手，实际供餐和临时调整以学校公告为准；各窗口菜单供分别选择。

每日菜单更新使用 **GPT-6 Luna（`gpt-6-luna`，`max`）**，模型和档位在定时工作流中明确指定。翻译与复核都通过学校网关的 **Responses API** 发送 `reasoning: {effort: "max"}`；该网关的 Chat Completions 路由不支持 Luna 的 `max`。网页访问不触发模型调用。API 密钥只保存在本地 `.env` 或 GitHub Actions Secret `TRANSLATE_API_KEY`，不进入网页。已发布菜单的翻译信息记录实际使用的模型、档位、复核方式与时间。

自动流程为 **API 初译 → 独立的第二次 API 复核并纠错 → 规则校验 → 发布**。复核会逐项对照韩文原文检查食材、菜名和做法，只有明确批准且通过规则校验的最终译文才能进入缓存。明确的韩元金额和时间需要与原文一致，允许等价的数字格式；缺译、未批准或结构错误时自动重试。任务在写入菜单文件前检查全部翻译字段，仍不完整则失败退出，保留上一份已发布数据。中文完整度统计展示窗口名、菜品和公告。

`scraper/menu_glossary.json` 仅作为 API 提示词的术语参考，不直接替换译文。旧菜单中已有的中文也必须经过当前流程，或命中同一流程已批准的缓存。缓存按接口、模型、档位、初译提示词、复核提示词及词表版本隔离。API 的临时错误最多重试三次，未完成的单项再进行一轮初译和复核；初译、复核及重试共用默认 600 秒的预算，避免故障时无休止调用。单独重译时保留菜单的原始抓取时间，译文处理时间单独记录在 `translation` 中。

外部失效监控预留了接口，默认关闭。需要接入时，添加 GitHub Actions Secret `HEALTHCHECK_PING_URL`（HTTPS 的 Healthchecks.io 兼容 Ping URL），并把仓库变量 `ENABLE_HEALTHCHECKS` 设为 `true`；每次定时任务结束会报告成功或失败。监控服务本身的超时告警需在服务端设置；这表示抓取任务状态，不是网页上线的独立核验。

## 开发与校验

静态根目录部署至 GitHub Pages，`python -m scraper.sync_site` 同步 `site/` 镜像。修改静态界面后同步镜像并更新 `sw.js` 的缓存版本。

```sh
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.cjs
python -m scraper.sync_site
```

推送界面修改时自动运行检查，不调用翻译 API。图标采用简约的白色线条碗形，浏览器标签、主屏图标与分享图保持一致；可安装 Pillow 后运行 `python tools/generate_icons.py` 重新生成。

抓取状态 `fetch_status` 区分成功、保留旧数据和失败；`menu_status` 单独记录 `available`、`empty`（解析阶段尚未判断原因）、`not_published`、`unavailable` 或 `closed`。`closure` 保存当天公告或周末空菜单规则的依据；`stale_reason` 区分来源已无菜单与抓取异常。未知原因不标记为“超出保留窗口”。

浏览器回归检查覆盖语言切换后刷新、分享链接选择保留、未公布菜单、历史数据提示、自动/手动选择与切换周后的跨月箭头。缓存回归另检查存储故障、标签页隔离和离线重开。先在另一个终端运行 `python -m http.server 8767 --bind 127.0.0.1 --directory site`，再在项目目录执行：

```sh
npx --yes --package @playwright/cli playwright-cli -s=menu-regressions open "http://127.0.0.1:8767/?lang=cn" --browser chrome
npx --yes --package @playwright/cli playwright-cli -s=menu-regressions run-code --filename tests/browser-regressions.js
npx --yes --package @playwright/cli playwright-cli -s=menu-regressions close
npx --yes --package @playwright/cli playwright-cli -s=menu-cache open "http://127.0.0.1:8767/?lang=cn" --browser chrome
npx --yes --package @playwright/cli playwright-cli -s=menu-cache run-code --filename tests/browser-cache-regressions.js
npx --yes --package @playwright/cli playwright-cli -s=menu-cache close
```

检查只在浏览器内存中构造数据，不调用翻译 API；本地输出保存在项目内已忽略的 `output/` 目录。

## 界面来源

当前界面适配 [Tabler](https://tabler.io/) 的页面、卡片和分段控件结构，使用本地 HTML/CSS，不引入完整组件库。日期导航位于内容顶部；宽度 ≥900px 时，电脑采用食堂选择区与菜单区两栏，手机和平板采用单栏。浅色页头和自然排布的更新时间替代原有上下黑栏。

早期界面参考 [Çukurova 大学食堂](https://www.cukurova.app/)。两个来源的 MIT 许可与版权说明均保留，详见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
